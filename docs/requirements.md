# 要件

この文書は、book-propsが何を作り、何を作らないかを確かめる参照である。
読者は、本を管理する利用者と、承認された仕様を実装する保守者である。
読者は、実装や受入の作業中に、利用動作、対象範囲、除外、未確定の設計条件、受入条件を確かめるために開く。
構成と現在のコードとの差は[アーキテクチャ](architecture.md)が説明し、この文書は利用者から見える動作と制約を述べる。
受入条件が実装と検査へ移され、この参照を読む必要がなくなった時に、この文書を取り除く。

## 根拠と決定状態

この仕様は、利用者が承認した全体仕様と、その後に確認した版・購入希望の扱いに基づく。

- 利用者は、役割を「ブラウザ：確認と登録／Obsidian：保持と記録」と定義した。
- 利用者は、この役割を具体化した全体仕様案を承認し、次のように答えた。

> OK、よいでしょう。
> book-props側の全ドキュメントを完全に書き換えてしまってよいです。

版は販売形態ではなく内容の違いで分け、購入希望は版を指定せず本に付ける。今回の購入と以前からの所有を記録する操作は分ける。

旧構成を選んだ過去の決定や承認前の提案を、現在の構成の根拠として流用しない。

| 状態 | 意味 | この文書での扱い |
| --- | --- | --- |
| `Known` | 利用者が明示した契約 | 上に記した役割分担と、版・購入希望の扱い |
| `Target` | 承認によって決めた変更先 | 断りのない要件はすべてこれであり、実装済みでも動作確認済みでもない |
| `Observed` | コードとテストから観測した事実 | 実装と検査の出典を添えて示す |
| `Unknown` | 現時点で判断できない事項 | [未確定の論点](#未確定の論点)に集め、確定した要件の根拠にしない |

動作を確認した環境と操作は[アーキテクチャの検証結果](architecture.md#新構成の実装と検証の入口)に記す。

画面の文言は仮である。
通信、保存キー、配置と接続契約は[アーキテクチャ](architecture.md)に記す。この文書は利用者が観測できる要件を扱う。

## 目的

重複購入を防ぎ、所有と購入希望を確かめて登録し、Obsidianで自然に読書記録を付けることを目的とする。
ブラウザは確認と登録を担い、Obsidianは保持と記録を担う。
二つの場所は同じ本の記録を使い、利用者が同じ情報を二か所へ書かなくて済むようにする。
例えば、初版を持っていてその本を「欲しい」に登録していれば、改訂版の商品ページで「別版を所持／欲しいに登録済み」と一行で分かる。
紙の本と電子書籍の両方を対象に含める。

| 場所 | 役割 | 利用者ができること |
| --- | --- | --- |
| ブラウザの拡張 | 確認と登録 | 商品ページで所有と購入希望を確認する、今回の購入を登録する、購入希望を付けたり外したりする、Obsidianで開く |
| Obsidian | 保持と記録 | 本ページと読書記録を保持する、本の購入希望と版ごとの所有・書誌を編集する、本棚で探す、実店舗で見た本やすでに持っている本を登録する |

## 用語

| 用語 | 意味 |
| --- | --- |
| 本 | 人から見て同じ一冊のまとまり。一つの本ページに対応する |
| 版 | 同じ本の中で、改訂・増補による内容の違いを区別する単位。紙と電子などの販売形態だけでは分けない |
| 所有 | 買った版を持っていること。貸借と譲渡を含まない |
| 購入希望 | 本を買いたいという意思の記録。版は指定しない。画面では「欲しい本」と呼ぶ。文言は仮 |
| 購入として登録 | 今回買ったことを記録する操作。買った版を所有にし、その本の購入希望を解除する |
| 所持を記録 | すでに持っていた版を記録する操作。その本の購入希望は変えない |
| 読書状態 | 本に付く、読書の進み具合 |
| 本ページ | 一つの本を保持する、ObsidianのMarkdownページ |
| Vault | 利用者が選ぶObsidianのVault。書籍を保存する範囲を接続の時に示す |
| 照合 | 商品ページから得た識別情報を、Vaultの記録と突き合わせて導く操作。結果は記録しない |
| 商品ページ | 対応サイトの商品詳細ページ |
| 拡張 | 書籍用のChrome拡張 |
| プラグイン | Obsidian書籍プラグイン |

## 書籍と版

一つの本につき、一つのMarkdownページを持つ。
一つの本ページに、その本の複数の版を保持できる。
本と版は内部IDを持ち、書名やファイル名を変えても内部IDは変わらない。
同じ書名の別の本を、互いに衝突させずに保持できる。
内部IDの置き場所と、ファイル名の付け方は未確定である。
改訂新版や第2版など、改訂・増補で内容が変わったものは、同じ本の別の版とする。
紙と電子、文庫と単行本など、販売形態だけの違いでは版を分けない。誤字修正だけの刷、カバー、価格改定、新品と中古の違いでも分けない。
セット商品と各巻は、別の本である。
原著と翻訳書も、別の本である。
所有は購入を意味し、貸借と譲渡は管理しない。
誤った本へ紐付いた版は、版の移動で直す。
版の移動やアーカイブで有効な版がなくなっても、本、購入希望、本文、タグ、読書状態は残る。

## 識別と所有判定

### 識別の規則

照合は二段で行う。
ISBNを入口に同じ本かを判定し、その本の中でどの版かを判定する。
ISBNは任意の値であり、ISBNを持たない書籍も記録できる。
ISBN-13に正規化して保存し、比較する。一つの版に複数のISBNが対応する場合は、どのISBNからも同じ版を見つけられるようにする。
ISBN-10は入力で受け付け、ISBN-13へ正規化する。
ISBNの入力はハイフンと空白を除いて検査し、確認数字が合わない場合は入力箇所で指摘する。
ISBNがない商品は、書名と著者で照合する。
書名と著者が同じ本が複数あっても、ISBNから一冊に特定できる場合は、その本を照合結果にする。
書名だけでは、同じ書名の別の本を所有と誤って示しうるので、書名だけの商品は判定不能とする。
ISBNを持たない書籍には、Kindle専売、同人誌、1981年より前の刊行などがある。
紙の書籍のAmazonのASINはISBN-10そのものだが、KindleのASINはISBNではない。
同じ本に所有記録があっても、商品の版を特定できなければ、所有記録あり・版未確認として扱い、同じ版の所有とは断定しない。
ISBNが違うだけでは、別の本とも別の版とも判定しない。例えば、同じ内容の紙と電子に異なるISBNが付いていても、同じ版として扱う。
似た書名だけで、同じ本とはしない。
ISBNが異なる商品を同じ本・同じ版または同じ本・別版と判定する根拠は、商品ページが示す版や別形式の情報、書誌、利用者の紐付けである。
形態が違うという情報だけでは内容の違いを確定しない。根拠を供給する経路によって判定の規則を変えない。
サイトのURLとサイト内の商品IDは、保存する識別子にしない。
URLは、商品情報を得る入力の経路である。

### 照合結果

照合の結果は、記録として保存せず、識別情報とその時点のVaultの記録から導出する。
所有側の結果は、次の五つである。

| 所有側の結果 | 条件 | 自動の通知 |
| --- | --- | --- |
| 同版所有 | 商品の版と同じ版が、所有として記録されている | 通知する |
| 別版所有 | 同じ本の別の版が所有として記録され、商品の版は所有されていない | 通知する |
| 所有記録あり・版未確認 | 同じ本の所有記録があるが、版を特定できず、同じ版か断定できない | 通知する |
| 未所有 | 識別情報が十分で、一致する所有記録がない | 購入希望もなければ通知しない |
| 判定不能 | 識別情報が足りない、接続できない、または記録を読めず、照合できない | 確認できないと通知する |

同じ本だと識別でき、その本に購入希望があれば、商品の版や所有側の結果にかかわらず通知に加える。
同版所有、別版所有、版未確認の表示に購入希望が加わる時は、一行に並べる。未所有と判定した場合は、購入希望だけを通知する。
確認できなかったものを、未所有として扱わない。

本をアーカイブすると、その本の全版と購入希望は照合に出ない。
版だけをアーカイブした場合、その版のISBNは本の特定には使うが、版の所有判定には使わない。
同じ本の有効な版の所有や、本の購入希望は変わらない。

## 項目

項目は、内部データ、標準項目、独自項目の三つに分ける。
内部データは、記録の一意性を担保する編集不可の値で、本と版の内部IDを指し、利用者に見せる必要はない。
標準項目は、商品ページの解析や書誌の取得と結び付き、自動で入力される項目である。
独自項目は、利用者が追加と削除をする、項目名と値の組である。

本に付く標準項目は、書名、著者、読了日である。
版に付く標準項目は、ISBN、版・版数、出版社、出版日、表紙、購入日、購入元である。
版ごとに管理する値は版に付け、本全体で共有する値は本に付ける。紙・電子などの形態は照合の手掛かりにできるが、管理項目にはしない。
読書状態、タグ、本文、所有、購入希望は、項目とは別の扱いである。
サイト内の商品IDは、標準項目にしない。

必須の項目は書名だけで、標準項目ごとに必須か任意かを持つ。
標準項目は削除できず、利用者は表示と非表示を切り替えられる。
すべての標準項目を、初めから表示する必要はない。
標準項目は、登録と編集の時に、検証、解析、正規化を行う。
独自項目は値を検証しないが、入力の時に、その型として読めるかだけを確かめる。
独自項目の型は、テキスト、数値、日付、はい・いいえ、選択肢の五つである。
標準項目の型も、この五つの型から派生させる。
ISBNがなくても、版の情報が不明でも、本と版を記録できる。
購入日と購入元は任意であり、購入日が空であることを、未所有と解釈しない。
価格は記録しない。
項目は並べ替え、範囲指定、検索に使い、タグは絞り込みに使う。

既存の記録へ書誌を補う時は、空の標準項目だけを埋める。
手で直した値、本文、タグ、読書状態を、取得した情報で上書きしない。

## 状態

所有、購入希望、読書状態は、別の概念として扱う。
所有は版に付く。
購入希望は本に付く。どの版を所有していても、またどの版も所有していなくても、購入希望を付けられる。
読書状態は本に付き、未読、読書中、再読中、読了、参照用のいずれかである。
どの状態からでも、どの状態へも変えられる。
参照用は、辞書のように通読しない本を表す。
積読という状態は置かない。
今回の購入、すでに持っていた版の記録、購入希望の追加・解除、所有の取消は、読書状態を変えない。
読書状態をタグで代用しない。
購入予定を、所有と購入希望の外にある第三の管理状態として増やさない。

### 購入希望と解除

購入希望は、特定の版ではなく、その本を買いたいことを表す。初版を所有したまま購入希望を付けられ、改訂版を開けば「別版を所持／欲しいに登録済み」と分かる。

その本のどれかの版を新たに買い、「購入として登録」すると、買った版を所有にし、本の購入希望を解除する。他の版の所有は変えない。
すでに持っている版を紙から電子に買い直した場合も、今回の購入として登録すれば購入希望を解除する。版の記録は増やさない。

「所持を記録」で昔買った版を追加したり、すでに記録した版を登録し直したりしても、購入希望は変えない。所有の記録の有無から、今回買ったかどうかを推測しない。
購入希望だけを外す操作は、その本の所有に影響しない。所有を取り消しても購入希望は変わらず、購入時に解除した希望も自動では戻さない。
購入希望の解除は拡張とObsidianで、所有の取消はObsidianで行う。

## タグ

タグは利用者が自由に付ける分類で、標準として決めたタグを持たない。
一つの本に、複数のタグを付けられる。
複数のタグを並べて探すと、すべてのタグが付いた本だけが見つかる。
検索欄で `#` を付けた語はタグだけを対象とし、同じ語が書名や著者に含まれていてもタグの代わりにはならない。
タグの除外条件と、タグの統合は持たない。
読了や未読のように、意味を解釈する値は、タグにしない。
タグの保存位置は実装上の選択であり、必須の保存形式は定めない。

## 本文とテンプレート

本ごとに、感想のような自由記述を書ける。
本文は自由なMarkdownであり、構造を縛らない。
本文を専用のフォームに閉じ込めず、ObsidianのMarkdownとして編集できる。
既存のMarkdownのリンク、タグ、添付を、そのまま使える。
標準のテンプレートは二つで、小説などの感想用と、実用書のメモ用である。
利用者は、テンプレートを追加と削除でき、本文を書く時に選べる。
テンプレートを使わなくてもよく、自分で作ってもよい。
標準テンプレートの具体的な内容と、Obsidianのどの仕組みで提供するかは要件では定めない。

## Chrome拡張

拡張は、商品ページでの確認と登録を担い、保持と記録はObsidianへ任せる。
初期の対象は、デスクトップのChromeである。
通信と認証は[接続と資格情報](architecture.md#接続と資格情報)に記す。この節は接続方式に依存しない動作を扱う。

### 自動の通知

対応サイトの商品詳細ページを開くと、自動で照合する。
結果は、画面の右上に出る短い一時通知で示し、通常は一行にする。
通知の例は、「この版を所持」、「別版を所持」、「欲しいに登録済み」、「別版を所持／欲しいに登録済み」である。
文言は仮である。
所有も購入希望も該当しない時は、自動で通知しない。
接続や識別に失敗した時は、確認できないと通知し、未所有として扱わない。
通知に、書名や書誌を再掲しない。
全版の一覧、大きな常設欄、サイドパネル、詳細画面を作らない。
通知は、ページのfocusを奪わない。
消えた通知は、右クリックの再確認で見直せる。
右クリックの再確認は、自動では通知しない未所有も含めて結果を示す。
拡張のアイコンに、所有のバッジを付けない。

### 操作メニュー

拡張のアイコンを押すと、小さな操作メニューが開く。
メニューの項目は、「購入として登録」、「欲しい本に追加」、「Obsidianで開く」である。
文言は仮である。
同じ本が購入希望済みなら、どの版の商品ページでも「欲しい本に追加」の代わりに解除を選べる。
所有の取消は、このメニューに置かず、Obsidianで行う。
未登録の本で「Obsidianで開く」を選ぶと、商品の情報を渡した登録画面へ進む。
開くだけでは、空の記録を作らない。

### 登録の挙動

「購入として登録」の対象は、通常は閲覧中の版であり、項目を選ぶだけで登録できる。再入力、確認ダイアログ、Obsidianへの画面切り替え、Vault同期の一時停止は要らない。
同じ本かを判定し、必要に応じて本を作る。購入時は、同じ版ならその版を使い、別版なら同じ本に追加する。
対象が一つに決まらない時だけ、候補の選択を求める。購入希望の登録では本を特定できればよく、版は選ばない。未登録の本は本ページだけを作り、購入希望を付ける。
接続先のVaultに保存できたことを確認してから、完了を通知する。他の端末への同期完了は待たない。
処理中の二重操作や再送で、本も版も増やさない。同じ購入の再送は新たな購入とみなさず、その後に付け直した購入希望も消さない。
既存の記録への書誌の補完は、[項目](#項目)の規則に従う。

### 失敗の扱い

| 状況 | 拡張の挙動 |
| --- | --- |
| Obsidianが起動していない、または接続できない | 確認できないと通知し、未所有として扱わない。Obsidianを開いて再確認するよう促す |
| 識別情報が足りず、商品を特定できない | 候補の選択か、Obsidianでの手入力へ進める |
| 保存されなかったと確認できた | 未保存だと伝え、入力を維持する。完了を通知しない |
| 保存を始めた後に結果を確認できない | 結果不明と伝え、入力を維持する。登録済みとも未保存とも断定せず、自動で書き直さない |
| 同じ本ページに未保存の編集があるなど、保存前に最新の状態を確認できない | 確認不能と伝え、書き込まずに入力を維持する |
| 保存の直前に、操作の判断や更新対象に関わる変更が見つかった | 上書きせず、[競合](#直接編集と競合)を示す。入力を保持し、記録を開いて確認できるようにする |
| 対応外のサイトや商品 | 自動では通知せず、Obsidianでの登録へ案内する |

## Obsidian

Obsidianは、本の保持と記録を担う。
ここに述べる画面や操作の名前は仮である。

### 本の登録

実店舗で買った本や見かけた本も、Obsidianから登録できる。
登録は、「本を登録」から始める。
本の指定の方法は、ISBN、書名の検索、対応する商品のURL、手入力の四つである。
本を指定した後で、「購入として登録」、「所持を記録」、「欲しい本に追加」のいずれかを選ぶ。
登録の前に照合の結果を示す。購入希望では版を選ばず、版の情報が不明でも購入や所有を記録できる。
照合に使った項目を変更した場合は、変更後の内容で照合し直してから登録する。
取得した書誌を選んだ後に別の本や版へ指定を変えた場合は、取得元の出版日や表紙を新しい記録に持ち込まない。
照合が判定不能でも、登録はできる。
URLから商品の情報を取得できない時は、失敗を伝え、ブラウザで開くか、手入力へ戻せる。
商品URLから取得するのは対応サイトの商品詳細だけとし、任意のURLをserverが取得する仕組みは採用しない。
ISBNと書名の検索は利用者が実行したときだけ国立国会図書館サーチへ問い合わせる。独自の全書籍データベースは持たない。

### 本ページ

本ページは、本の基本プロパティと購入希望・読書状態、版ごとの所有と書誌、自由なMarkdownの本文から成る。
基本のプロパティは、Obsidian標準のプロパティで扱う。
版のように繰り返す入れ子の部分は、プラグインが編集を補う。
Obsidian標準のプロパティだけで、版ごとの入れ子の項目を編集できるとは約束しない。
YAMLのキーとファイル構造は[記録の表現](architecture.md#記録の表現)に記す。

### 本棚

本棚では、所有、購入希望、読書状態で絞り込める。
書名、著者、出版社、タグ、購入日などで、検索と並べ替えができる。
著者から同じ著者の本を、出版社からその出版社の版を含む本を表示できる。
登録していない本は、書店の検索へ移って探せる。

### 版と所有の操作

版の追加と編集、版の別の本への移動、版のアーカイブ、所有の取消は、Obsidianで行う。
誤った本へ紐付いた版は、版の移動で直す。

## 対応サイト

初期の対応サイトは、Amazon、楽天ブックス、バリューブックス、BOOKOFFの四つである。
初期対応を一つに絞ると、そのサイトに閉じた設計になりうるため、複数を対象にする。
サイトごとに、商品ページから識別情報を取り出す抽出が異なり、照合の規則は共通である。
自動の照合は、商品詳細ページに限る。
実際の商品詳細での抽出結果は[検証記録](architecture.md#新構成の実装と検証の入口)を参照する。
利用者は対応サイトの一覧を閲覧し、各サイトへ移れる。一覧は編集できない。表示場所は要件では定めない。

## 保存先

### 正本

正本は、利用者が選んだVaultの本記録だけである。
拡張とObsidianは、同じ記録を使う。
別のデータベースや独立した本棚を、常時二重に管理しない。
一冊は一つのまとまりとして保存され、その配下に版が付く。
保存の表現は、Obsidianで人が読み書きする自然な形にする。
Vaultをどこにどう保管し、同期するかは制限しない。

### 構成

採用する構成は、専用のブラウザ拡張、Obsidian書籍プラグイン、Vaultの三つである。
プラグインが、拡張の要求の受付、照合、保存を担い、サーバーの役を果たす。
独立したbackendや別のデータベースを、必須としない。
初期実装の接続・認証とRustの組み込みは[採用した構成](architecture.md#採用した構成)に記す。

### 接続と資格情報

接続の時に、対象のVaultと書籍の保存範囲を明示し、接続を認証する。
商品のページへ、資格情報や本文を渡さず、必要な結果だけを渡す。
既存の公式Web Clipperは、記事や単語の取り込みに使い続け、その設定を変えない。

### 直接編集と競合

保存の直前に最新の記録を確認し、Obsidianでの直接編集を正規の変更として尊重する。競合とするのは、操作を進める判断に使った内容、または操作が変更する内容が変わった場合である。ページ全体が変わったという理由だけでは止めない。

| 操作中に見つかった変更 | 扱い |
| --- | --- |
| 本文、タグ、読書状態など、その操作が判断にも変更にも使わない項目を編集した | 編集を残して保存を続ける。書籍の保存範囲内で、本ID・版IDと照合結果が変わらないファイル名の変更も同じ。 |
| 書誌の補完先だった空欄を利用者が埋めた | 照合結果が変わらなければ、補完だけを省き、その値を残して保存を続ける。 |
| 照合結果が変わり、対象の本・版が変わったか一意に決まらなくなった。対象が削除・アーカイブされたか、対象版が別の本へ移った | 競合。別の本・版へ黙って付け替えたり、消えた記録を作り直したりしない。 |
| 購入を確定する前に、対象版の所有または本の購入希望が変わった | 競合。所有と購入希望の一方だけも変えない。処理中に「欲しい」を外して付け直したと分かる場合も、比較時の値が同じという理由で消さない。 |

「所持を記録」は購入希望を判断にも変更にも使わないため、購入希望だけが変わっても止めない。購入希望だけを変更する操作は版の所有を変更せず、本の特定に影響しない所有変更では止めない。確定済みの同じ購入要求は新たに判定せず、元の結果を返す。

必要な記録を読めないときは「読めない記録」、対象の本ページに未保存の編集があるなど、接続先の最新状態を確認できないときは「確認不能」として書き込まない。競合が見つかった場合も更新を一切適用せず、入力を保持し、利用者が該当記録を確認した上でやり直せるようにする。

### 端末と同期

スマホでの記録の利用は、既存のVault同期を使う設計であり、独自の同期を持たない。
照合は、プラグインが接続先のVaultで読める記録だけを根拠とし、未同期の変更まで保証しない。
登録のために同期を停止したり、同期方式を限定したりしない。最終確認に間に合った外部更新には、[直接編集と同じ判定](#直接編集と競合)を適用する。最終確認と保存の間に同期ツールや別のアプリが同じファイルを書き換えると、プラグインの保存がその変更を検知せずに上書きすることがある。保存完了の通知は、接続先のVaultで登録を確認したことを示すもので、外部の変更をすべて保持できたことまでは保証しない。
スマホのブラウザでの自動照合と、バーコードの読み取りは、今回の対象外である。
スマホでの動作は確認していない。

## 入出力と削除

入出力はJSONで行い、維持する。
JSONは書籍ごとのMarkdownと内部IDを含む版付きの形式で、購入結果の再確認記録は持ち込まない。空の書籍範囲に取り込み、既存の本ページは上書きしない。
取り込み中に同じ本IDのページが見つかった場合、Markdownが同じなら新たに作らず、異なればそれ以上の取り込みを止める。
誤って登録した本や版を取り下げるときは、アーカイブする。記録はVaultに残り、Obsidianの管理画面から期限なく復元できる。自動削除は行わない。
版の移動を維持する。
移動中の外部更新で両ページから版がなくなっても、移動を行った端末の控えからその版を取り出せる。
控えは所有に数えず、利用者が管理画面から復元するまで本ページは書き換えない。
版だけをアーカイブしても、本ページ、購入希望、本文、タグ、読書状態は残る。
同じ本や版を再登録しようとしてアーカイブ済みの記録と重複するときは、自動で上書き・復元したり、別の記録を増やしたりしない。管理画面で元の記録を確認する。

## 公開と配布

ソースリポジトリは公開し、コードと文書には [MIT ライセンス](../LICENSE)を適用する。
Chrome 拡張と Obsidian プラグインは、同じ版の ZIP 一つにまとめて GitHub Releases で配布する。
初回は ZIP を展開し、両方を手動で読み込む。
新版に更新するときも、両方を同じ版に手動で差し替える。
Chrome Web Store と Obsidian Community Plugins には掲載しない。

## 除外事項

価格を記録しない。
借りた、貸した、譲渡したといった管理をしない。
商品の検索結果一覧へ、所有のバッジを付けない。
拡張のアイコンへ、所有のバッジを付けない。
固定の標準タグを持たない。
タグの除外条件と統合を持たない。
独自の全書籍データベースを持たない。
複数の正本を、常時同期しない。
Obsidianの既存の同期の外に、独自の同期を持たない。
任意のURLをserverが取得する仕組みを、新しく採用しない。
所有判定の速さとオフライン対応を、要件として立てない。
スマホのブラウザでの自動照合とバーコードの読み取りは、今回の対象外である。

## 後に回すもの

他のサービスからの一括インポートは、初期の範囲に含めず、後に回す。
戻す時期は決めていない。
後から追加しても問題が出ない作りにしておく。

### 保存と競合の条件

対応する要件群は、[保存先](#保存先)、[Chrome拡張](#chrome拡張)である。

| 条件 | 前提 | 操作 | 期待結果 | 状態 |
| --- | --- | --- | --- | --- |
| 直接編集の尊重 | Obsidianで本ページの本文を直接編集し、保存した。本に購入希望はない | 拡張から、別の版を「購入として登録」で保存する | 本文の編集が残り、版が加わる | 未実行 |
| 保存待ちの無関係な編集 | 購入のために本ページを読み取った後、Obsidianで本文と読書状態を変え、その変更が保存された。本・版・所有・購入希望は変わっていない | 拡張からの購入を確定する | 新しい本文と読書状態を保ち、購入を保存する | 未実行 |
| 保存待ちのファイル名変更 | 購入の対象を決めた後、書籍の保存範囲内で本ページのファイル名だけが変わった。本ID・版IDは変わっていない | 拡張から購入を確定する | 名前を変えたページに保存し、元のファイル名のページを作らない | 未実行 |
| 先に埋まった補完欄 | 保存を待つ間に、補完対象だった出版社の空欄を利用者が埋めた。照合結果は変わっていない | 購入を確定する | 利用者が入力した出版社のまま、購入を保存する | 未実行 |
| 購入希望との競合 | 購入のために本ページを読み取った後、同じ本に購入希望が付いた、または外して付け直したことが確認できた | 購入を確定しようとする | 競合を示し、入力を保持する。新しい購入希望も版の所有も変わらない | 未実行 |
| 所有との競合 | 購入のために対象版を読み取った後、その版の所有が変更された | 購入を確定しようとする | 競合を示す。最新の所有と購入希望はどちらも変わらない | 未実行 |
| 版の移動との競合 | 購入の対象版が、照合に使った本から別の本へ移動された | 元の要求のまま購入を確定しようとする | 競合を示す。元の本への版の再作成も、移動先での購入確定も行わない | 未実行 |
| 照合結果との競合 | 購入の対象を一つに決めた後、同じ商品に該当する別の候補が加わった | 拡張から購入を確定しようとする | 競合を示す。どちらにも書き込まず、候補を選び直せる | 未実行 |
| 購入希望に依存しない既存所持の記録 | 所持の記録のために本ページを読み取った後、購入希望が付いた。それ以外の判定条件は同じ | Obsidianで所持を確定する | 版が所有となり、後から付いた購入希望が残る | 未実行 |
| 未保存の編集 | 対象の本ページをObsidianで開き、本文を変更したがディスクにはまだ反映されていない | 拡張から購入を保存しようとする | 確認不能と伝え、入力を保持する。エディターの入力とディスク上の記録を変更しない | 未実行 |
| 読めない記録 | 本ページのプロパティが壊れ、読めない | その本の商品ページを開く | 読めない記録として示され、修正へ進める。未所有とは通知しない | 未実行 |
| 未保存と確認できた購入 | 本に購入希望があり、書き込みの開始前に保存先が使えなくなる | 「購入として登録」を選ぶ | 版の所有も本の購入希望も変わらない。未保存と分かり、入力が維持され、完了は通知されない | 未実行 |
| 同期の限界 | 別の端末で所有を登録し、Vaultの同期が未完了である | この端末で商品ページを開く | 通知は、このVaultで読める記録だけから導かれる。未同期の記録が反映されなくても、不具合とはみなさない | 未実行 |
| 同期を止めない通常登録 | Vaultの同期が有効で、対象の本・版は一つに決まり、本ページに競合する変更がない | 改訂版の商品ページで「購入として登録」を選ぶ | 同期を止めず、Obsidianに画面を切り替えずに、同じ本ページへ購入を保存する。接続先のVaultで保存を確認した時点で完了を通知する | 未実行 |
| 最終確認に間に合った外部の本文編集 | 購入対象を決めた後、最終確認の前に外部ツールが同じ本ページの本文だけを変える | 拡張から購入を確定する | 新しい本文を残して購入を保存する | 未実行 |
| 最終確認に間に合った外部の購入希望変更 | 購入対象を決めた後、最終確認の前に外部ツールが同じ本ページに購入希望を付ける | 拡張から購入を確定しようとする | 競合を示し、入力を保持する。新しい購入希望も対象版の所有も変えない | 未実行 |
| 保存後に結果を確認できない購入 | 購入を書き込んだ直後、結果を確認する前に外部ツールが本ページを置き換え、適用済みの要求を確認できなくなる | 「購入として登録」の結果を拡張で確認する | 結果不明と伝え、入力を保持する。完了も未保存も通知せず、外部ツールが置いたページを自動で書き直さない | 未実行 |
